# 컴파일과 PDF

## 컴파일러와 기본 문서

프로젝트 설정에 **컴파일러**와 **기본 문서**가 있습니다.

- **자동**(새 프로젝트의 기본값): 빌드할 때마다 문서를 보고 고릅니다. 프리앰블(그 안에서 `\input`하는 파일과 프로젝트 자체의 `.sty`/`.cls` 포함)이 `ctex`, `xeCJK`, `fontspec`, `unicode-math` 등을 불러오거나 클래스가 `ctexart`/`ctexbook` 등이면 XeLaTeX, `luacode`나 `luatexja`를 불러오면 LuaLaTeX, 그 밖에는 pdfLaTeX를 씁니다. 첫 줄의 `% !TEX program = xelatex`나 프로젝트의 `latexmkrc`가 있으면 그것을 따릅니다.
- **pdfLaTeX**: 영어 문서에 흔히 쓰는 선택입니다.
- **XeLaTeX**: 중국어(ctex)와 시스템 글꼴에 필요합니다.
- **LuaLaTeX**: 시스템 글꼴도 지원합니다.

엔진을 직접 고르면 감지 없이 항상 그 엔진을 사용합니다.

> 중국어 문서는 `\usepackage[UTF8]{ctex}`를 불러오면(또는 `ctexart` 클래스를 사용하면) 자동이 XeLaTeX로 전환됩니다. ctex 없이 중국어 텍스트를 쓰면 pdfLaTeX에서 “Unicode character … not set up for use with LaTeX” 오류로 실패합니다.

기본 문서는 빌드가 시작되는 파일입니다. 프로젝트 설정의 **기본 문서**에서 고르세요.

빌드는 전체 TeX Live와 latexmk를 사용하며, latexmk가 LaTeX, BibTeX/Biber, 색인을 필요한 만큼 반복 실행합니다. 빌드는 네트워크 접근 없이 격리된 환경에서 실행되며, shell escape는 제한됩니다.

## 컴파일 옵션

**다시 컴파일** 옆의 화살표에는 다음이 있습니다.

- **자동 컴파일**: 입력을 잠시 멈추면 빌드합니다(입력하는 사람이 몇 명이든 프로젝트당 한 번에 하나의 빌드).
- **컴파일 모드**: 일반 또는 빠르게 [초안]. 초안 모드는 이미지를 빼고 더 빠르게 빌드합니다.
- **컴파일 오류 처리**: 첫 오류에서 중지하거나, 오류가 있어도 컴파일을 시도합니다.
- **캐시 지우고 다시 컴파일**: 빌드 결과가 이상할 때 보조 파일을 지우고 처음부터 빌드합니다.

이 옵션은 이 브라우저에 프로젝트별로 저장됩니다.

## 로그

**로그**에 표시된 숫자는 오류 개수입니다. 로그에는 오류, 경고, 조판 문제가 나열됩니다.

- 각 항목에 LaTeX 메시지가 있고, 흔한 문제에는 설명이 붙습니다(예: 패키지가 빠진 경우 추가할 패키지 이름을 알려 줍니다).
- 항목을 클릭하면 해당 파일과 행으로 이동합니다.
- 원본 로그도 볼 수 있으며, AI가 오류를 설명하거나 고칠 수 있습니다.

> 빌드가 실패하면 마지막으로 성공한 빌드의 PDF가 화면에 그대로 남습니다.

## 소스와 PDF 사이 이동

- **소스 → PDF**: 커서를 소스에 둔 채 PDF 막대의 **위치 찾기**(또는 오른쪽 클릭 메뉴의 "PDF에서 위치 보기")를 클릭하면 PDF가 그 위치로 스크롤되고 강조 표시됩니다.
- **PDF → 소스**: PDF를 더블클릭하면 편집기가 해당 파일의 그 행을 엽니다.

## 레이아웃: 편집기, PDF 또는 둘 다

보기 전환(PDF 막대 오른쪽의 작은 버튼 네 개)으로 Overleaf처럼 **편집기만**, **편집기 및 PDF**(나란히) 또는 **PDF만**을 표시하며, 네 번째 버튼은 PDF를 새 창에서 엽니다. 이 브라우저가 선택을 기억합니다. 구분선을 한쪽 끝까지 끌어도 그쪽 창이 숨겨집니다.

- 편집기만 표시할 때는 **다시 컴파일**과 같은 전환 버튼이 편집기 도구 모음 끝에 있습니다.
- 편집기에서 **PDF에서 위치 보기**를 하면 숨겨진 PDF가 표시됩니다.
- 좁은 창(태블릿이나 휴대폰)에서는 한 번에 하나만 표시할 공간이 있으며, 사이드 패널(파일, 검색 등)은 열려 있는 동안 편집기를 덮습니다.

## 별도 창의 PDF

**새 창에서 PDF 열기**(보기 전환의 마지막 버튼)는 PDF를 별도 창에서 엽니다. 이 창은 다른 화면으로 옮길 수 있습니다.

- 편집기 창에서는 PDF 창이 빠지고 편집기가 창 전체를 차지합니다. **다시 컴파일**은 편집기 도구 모음 끝으로 옮겨집니다.
- PDF 창에는 다시 컴파일, 로그, PDF에서 위치 보기, 다운로드가 있습니다. PDF를 더블클릭하면 편집기 창의 소스로 이동합니다.
- 편집기 도구 모음의 **여기에 PDF 표시**를 누르거나 창을 닫으면 PDF 창이 다시 돌아옵니다.

## 다운로드

- PDF 막대에서 현재 PDF를 다운로드합니다.
- 파일 트리 상단의 다운로드 버튼은 프로젝트 소스 파일을 .zip으로 다운로드합니다.
- 프로젝트 목록의 프로젝트 메뉴(⋯)에는 먼저 빌드한 뒤 내려받는 **PDF 다운로드**와 모든 소스 파일을 내려받는 **.zip 다운로드**가 있습니다.

## Word로 내보내기

Word 파일만 받는 저널도 있습니다. 프로젝트 목록의 프로젝트 메뉴(⋯)나 프로젝트 설정의 **작업**에 있는 **Word로 내보내기…**는 프로젝트를 .docx로 바꿉니다.

- 제목 페이지는 문서에서 가져옵니다. 템플릿 변환이 읽을 수 있는 클래스(Springer Nature `sn-jnl`, Elsevier, Elsevier CAS, OUP, BMC, IEEE, ACM, LNCS, REVTeX, `article`)에서 제목, 저자, 소속, 교신저자, 초록, 키워드를 읽습니다.
- 수식은 Word 수식이 됩니다. 그림과 표 번호는 Word가 매기고, PDF와 EPS 그림은 이미지로 바뀝니다. 번호가 있는 수식은 번호를 유지하므로 `\eqref`도 그대로 가리킵니다.
- 표는 편집할 수 있는 Word 표가 되며, 병합된 셀도 유지됩니다. 참고문헌 목록은 원래 참고문헌이 있던 자리에 제목(References 또는 문서에서 정한 제목)과 함께 들어가고, 본문의 인용은 해당 항목으로 연결됩니다.
- **인용 스타일**: **문서와 같게**는 문서의 참고문헌 스타일을 따릅니다. APA, Vancouver, AMA, IEEE, Nature, Chicago 또는 프로젝트에 올린 `.csl` 파일을 고를 수도 있습니다.
- **Word 템플릿**: 저널의 Word 템플릿(`.docx`)을 프로젝트에 올리고 여기서 고르면 문서가 그 스타일을 따릅니다. 이 항목은 프로젝트에 `.docx` 파일이 있을 때 나타납니다.
- 보내기 전에 결과를 확인하세요. 직접 만든 매크로와 복잡한 표는 Word에서 고쳐야 할 수 있습니다. TikZ 그림은 변환되지 않으니 먼저 이미지로 컴파일해 그 이미지를 넣으세요.
