# 管理

システム管理者には、アバターメニューの **設定** の下に管理ページが表示されます。管理者には、自分のチーム向けの **ユーザーを管理** と **招待** が表示されます。

## ユーザーと招待

- 一般公開のアカウント登録はありません。アカウントは招待リンクからのみ作成され、プロジェクトはアカウントを持つユーザーとだけ共有されます。
- アカウントには次の 3 つのロールのいずれかがあります。
  - **メンバー**。
  - **管理者**：**チーム** を率います（指導教員とその学生など）。管理者が招待したメンバーは管理者のチームに加わり、管理者はそのメンバーだけを管理します。
  - **システム管理者**：初回セットアップで作成したアカウントの 1 つだけです。インスタンス全体（AI サービス、バックアップ、ネットワーク）を運用し、全員を見ることができます。2 人目を任命することはできないため、1 つの管理者アカウントがインスタンスを乗っ取ることはできません。
- **招待**：1 回だけ使えるリンクで、1 つのメールアドレス宛て、または（メールアドレスを空欄にすると）リンクを知っている全員向けに、有効期限付きで作成します。保留中の招待のリンクは一覧に残り（**リンク**）、ColTex にアクセスできるアドレス（LAN、Tailscale、Cloudflare）ごとに 1 つずつあります。システム管理者はメンバーまたは管理者を招待でき、新しいアカウントの **AI グループ** を選びます。管理者はメンバーだけを自分のチームに招待でき、そのメンバーには管理者の AI グループが適用されます。管理者が表示・取り消しできるのは自分の招待だけです。
- **ユーザーを管理**：システム管理者はすべてのアカウントを表示し、ユーザーをメンバーまたは管理者にしたり、メンバーをチーム間で移動したり（行のメニューの **チーム**）、パスワードをリセットしたり、アカウントを停止または削除したりできます。管理者には自分と自分のチームが表示され、パスワードのリセット、停止、削除は自分のチームのメンバーに対してのみ行えます。アカウントを削除すると、そのアカウントが所有するプロジェクトも削除されます。
- システム管理者のロールを他のユーザーに譲る（またはそのアカウントを失ったときに取り戻す）には、サーバーで `coltex cli system-admin <email>` を実行します。以前のシステム管理者は管理者になります。

## AI サービス

- **AI サービス**：API キーまたはサブスクリプションのログイン（Claude Pro/Max、ChatGPT、Copilot など）でプロバイダーを接続するか、独自の OpenAI 互換サーバー（Ollama、vLLM、LM Studio など）を接続します。キーは暗号化して保存され、メンバーには表示されません。リクエストはこのサーバーを経由します。
- サブスクリプションのログインが、表示されない localhost のアドレスで終わった場合は、アドレスバーからそのアドレス全体をコピーして ColTex に貼り付けてください。
- **自動** の 3 つのモデルを設定すると、全員が自動選択で始めます。**判定モデル**（安価で高速なモデル）が各メッセージを読み、**軽量モデル**（簡単な質問、小さな修正）または **高性能モデル**（複数のエラー、複数ファイルにまたがる変更、丁寧な文章）に割り振ります。3 つすべてが設定されるまでは、各ユーザーは利用できる最初のモデルで始めます。
- **AI の利用状況とアクセス**：グループ全体と個人ごとのリクエストとトークン。誰がどのモデルを使えるかは **AI グループ** で設定します。各グループでは、プロバイダー（後から追加されるモデルを含む）または個々のモデルを許可します。たとえば「博士課程の学生」には高性能モデル、「学部生」には軽量モデル、といった具合です。各ユーザーが所属できるグループは最大 1 つで、招待時に選ぶか、後で一覧からそのユーザーを開いて選びます。どのグループにも属していないユーザーは AI エージェントを利用できないため、新しいユーザーはシステム管理者が追加するまで AI を使えません（管理者が招待したメンバーには管理者のグループが適用されます）。システム管理者は常にすべてのモデルを利用できます。グループを削除すると、そのユーザーは別のグループに参加するまで AI を使えなくなります。

  グループでは、各メンバーの 1 日、1 週間、1 か月あたりの利用量を、トークン、コスト（定価ベース）、またはその両方で制限することもできます。メンバーが上限に達すると、次の期間が始まる（暦日、月曜始まりの週、暦月。サーバーのタイムゾーン基準）までメッセージは拒否されます。上限を超えることになったメッセージ自体は最後まで処理されます。メンバーは AI エージェントのメッセージ入力欄の下で利用量を確認できます。システム管理者には上限はありません。

  1 人だけ設定を変えるには、一覧でそのユーザーを開きます。**カスタマイズ** の下の **個別のモデルアクセス** と **個別の利用上限** は、オンにしている間グループの設定に代わって適用されます（個別のアクセスはグループなしでも機能します）。一覧ではそのユーザーに **カスタマイズ済み** と表示されます。

## ストレージとバックアップ

- プロジェクトのファイルは、サーバーの起動時の設定（`STORAGE` と `S3_*`）に従って、ローカルディスクまたは S3 互換ストレージに保存されます。履歴、ビルドの出力、コンパイラの作業コピーはデータディレクトリに残ります。
- **WebDAV バックアップ** は、Nextcloud、ownCloud、NAS、その他の WebDAV サーバー上のフォルダーに保存されます。各バックアップは、データベース、すべてのプロジェクトのファイルとその履歴を含む 1 つのファイルです。毎日または毎週のスケジュールを設定し、保持する数を選べます。サーバーがアプリパスワードに対応している場合は、それを使ってください。
> **暗号化**：暗号化されたバックアップ（AES-256）にはインスタンスのシークレットも含まれるため、復元後も接続済みの AI サービスをそのまま使えます。**このパスワードは別の場所に保管してください。パスワードがないとバックアップを開けません。**
- 復元は、サーバーを停止した状態でサーバー上の `restore` コマンドで行います。運用ガイドを参照してください。

## 監視

**概要** には、サーバー、コンパイラ、データベースのリアルタイムの状態と、CPU、メモリ、ビルドの推移グラフが表示されます。サーバーは 10 秒ごとにサンプリングし、30 日間保持します。ページを誰も開いていない間も記録されます。

## ネットワーク

**ネットワーク** には、ColTex にアクセスできるアドレス（招待と Git のアドレスに使われます）が一覧表示され、組み込みの Tailscale と Cloudflare Tunnel をオンにでき、リクエストがサーバーに届く経路が表示されます。[デプロイとネットワーク](#/help/deployment) を参照してください。
