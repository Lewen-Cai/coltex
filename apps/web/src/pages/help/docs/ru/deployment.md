# Развёртывание и сеть

В рабочем режиме ColTex использует один порт (по умолчанию 3690): через него идут страницы, API, совместное редактирование в реальном времени (WebSocket) и уведомления. Подойдёт всё, что пробрасывает HTTP и WebSocket: этот компьютер, локальная сеть, Tailscale, Cloudflare Tunnel или облачный сервер. (3000 и 5173 — порты сервера разработки.)

## Установка

В Linux или macOS с Docker — одна команда:

```sh
curl -fsSL https://raw.githubusercontent.com/Lewen-Cai/coltex/main/install.sh | bash
```

Она спрашивает язык, редакцию и то, как люди будут открывать ColTex (выбор стрелками; вместо ответов можно передать параметры, например `--edition`, `--domain` или `--lang`), проверяет Docker (в Linux может его установить), загружает ColTex в `~/coltex`, записывает настройки, скачивает готовые образы (x86-64 и ARM64), запускает ColTex и выводит адреса, которые нужно открыть на этой машине и в вашей сети. При первом запуске скачивается TeX Live. Есть две редакции:

| Редакция | Загрузка | На диске (весь ColTex) | Нужно свободного места |
| --- | --- | --- | --- |
| **standard** (по умолчанию) | около 3 ГБ | около 12 ГБ | 20 ГБ |
| **full** (`--edition full`) | около 8 ГБ | около 23 ГБ | 35 ГБ |

Обе компилируют одинаково (полный TeX Live). Редакция full добавляет руководства и исходники пакетов, которые затем может читать ИИ-агент; в редакции standard он отвечает по файлам пакетов и собственным знаниям. Переключиться позже можно командой `coltex edition full` или `coltex edition standard`.

Удалённый доступ можно включить сразу:

```sh
curl -fsSL https://raw.githubusercontent.com/Lewen-Cai/coltex/main/install.sh | bash -s -- --tailscale
curl -fsSL https://raw.githubusercontent.com/Lewen-Cai/coltex/main/install.sh | bash -s -- --cloudflare-token <token>
curl -fsSL https://raw.githubusercontent.com/Lewen-Cai/coltex/main/install.sh | bash -s -- --domain tex.example.org   # a cloud server with its own domain: HTTPS
```

Дальше ColTex управляется командой `coltex`:

| Команда | Что делает |
| --- | --- |
| `coltex status` / `logs` | Состояние / журналы |
| `coltex edition [standard\|full]` | Показать или сменить редакцию TeX Live (скачивает другой образ компилятора) |
| `coltex update` | Обновить до последнего выпуска (скачивает новые образы); данные и настройки сохраняются |
| `coltex stop` / `start` | Остановить / запустить |
| `coltex tailscale up` | Подключиться к вашему tailnet (выводит ссылку для входа и QR-код) |
| `coltex cloudflare quick` | Временный публичный адрес Cloudflare |
| `coltex cloudflare token` | Туннель Cloudflare с вашим собственным доменом (запрашивает токен) |

## Вход с любого адреса

Сервер принимает вход, выполненный на его собственном адресе: откройте его по `localhost`, IP в локальной сети, адресу Tailscale или домену, ничего заранее не перечисляя. Страница на другом сайте не может выполнить вход за кого-либо.

## Какие адреса используют ссылки

Ссылки-приглашения и адреса для клонирования через Git предлагаются по одному разу для каждого адреса, по которому доступен ColTex, у каждого своя кнопка копирования, так что вы выбираете тот, который сможет открыть получатель:

- **Локальная сеть** или **Tailscale**: адрес, по которому вы открыли ColTex (распознаётся по самому адресу);
- **Tailscale**, **Cloudflare**: адреса встроенных Tailscale или Cloudflare Tunnel, пока они подключены. Они появляются и исчезают вместе с ними; при отключении ничего менять не нужно;
- **Публичный адрес**: `COLTEX_URL` сервера, если он задан.

Ссылки ожидающего приглашения остаются в списке приглашений, пока оно не будет использовано или не истечёт.

## Tailscale

В ColTex встроен Tailscale: он может подключиться к вашему tailnet как отдельное устройство (по умолчанию с именем `coltex`). На сервер ничего устанавливать не нужно, и это работает на серверах без графического окружения.

1. В разделе **Настройки → Сеть** включите Tailscale.
2. Отсканируйте QR-код телефоном или откройте ссылку на любом устройстве и войдите в свой tailnet. Страница сама переключится в состояние «Подключено».
3. Включите **Открыть ColTex в tailnet**. Если для tailnet включены MagicDNS и HTTPS, адрес будет `https://coltex.<your tailnet>.ts.net`, иначе `http://coltex.<your tailnet>.ts.net`.

Если ни один браузер пока не может открыть страницу настроек, выполните на сервере:

```sh
coltex tailscale up
```

Команда включает Tailscale, выводит в терминал ссылку для входа и QR-код, ждёт входа, а затем открывает ColTex в tailnet. `coltex tailscale status` показывает состояние, `coltex tailscale down` выходит из tailnet, `coltex tailscale off` отключает Tailscale.

`TS_HOSTNAME` меняет имя устройства. Сервер сам запускает Tailscale: никаких дополнительных контейнеров или привилегий. Ключи устройства хранятся в `data/tailscale` и не попадают в резервные копии; после восстановления войдите снова.

Если на сервере уже работает собственный Tailscale, встроенный не нужен: откройте ColTex по IP-адресу Tailscale сервера или имени MagicDNS с портом `:3690`.

## Cloudflare Tunnel

В ColTex встроен и Cloudflare Tunnel — только как туннель: люди по-прежнему входят под своими учётными записями ColTex; Cloudflare Access не нужен. Открытый порт на сервере не требуется.

- **Быстрый туннель**: без учётной записи Cloudflare; вы получаете `https://<random>.trycloudflare.com`, который меняется при каждом запуске. Для пробы.
- **Свой домен**: если ваш домен обслуживается Cloudflare, создайте туннель в разделе Zero Trust → Networks → Tunnels и скопируйте команду под заголовком «Run the following command» (для любой системы: Windows, macOS, Debian, Red Hat или Docker) — ColTex сам извлечёт из неё токен; добавьте туннелю публичное имя хоста (например, `tex.example.org`) с сервисом `http://localhost:3690`.

Включите его переключателем на карточке Cloudflare Tunnel в разделе **Настройки → Сеть**, затем выберите временную ссылку или туннель (сохранённый или новый из вставленной команды), либо в терминале командой `coltex cloudflare quick` / `coltex cloudflare token`. После подключения его адреса сами появляются в ссылках-приглашениях. Токен хранится в зашифрованном виде и больше не показывается.

## Настройки сервера

Это переменные окружения сервера. С Docker запишите их в файл `.env` рядом с `docker-compose.yml` и выполните `docker compose up -d`.

| Переменная | Что делает |
| --- | --- |
| `COLTEX_PORT` | Порт, по умолчанию 3690 |
| `COLTEX_URL` | Публичный адрес, предлагаемый в каждой ссылке, например `https://tex.example.org` |
| `TRUSTED_ORIGINS` | Другие адреса, с которых принимается вход, через запятую. Нужно, только если страницы и API находятся по разным адресам |
| `TRUST_PROXY` | Если перед сервером стоит обратный прокси (Caddy, Nginx): `uniquelocal` (прокси в частной сети) или `true`. Если не задано, сервер принимает прокси за посетителя, и все делят одно ограничение частоты входа |
| `TS_HOSTNAME` | Имя устройства встроенного Tailscale, по умолчанию `coltex` |

Блок **Как приходят запросы** внизу раздела **Настройки → Сеть** показывает эти настройки и IP, который видит сервер, и указывает на проблемы.

## Типичные конфигурации

| Конфигурация | Как |
| --- | --- |
| Только этот компьютер | Настройки по умолчанию: `http://localhost:3690` |
| Локальная сеть | Откройте по адресу сервера в локальной сети, например `http://192.168.1.20:3690`. Адреса в локальной сети могут меняться; для долгой работы закрепите адрес в роутере |
| Tailscale | См. раздел Tailscale выше |
| Cloudflare Tunnel | См. раздел Cloudflare Tunnel выше |
| Облачный сервер | С доменом: установите с `--domain tex.example.org` (направьте DNS домена на сервер и откройте порты 80 и 443). Встроенный Caddy получает сертификат HTTPS; порт 3690 тогда отвечает только на самом сервере. Без домена: Cloudflare Tunnel или Tailscale |

## Безопасность

- Для небольшой группы проще всего открывать ColTex только через Tailscale или VPN: тогда его вообще не видно из интернета. С Cloudflare Tunnel он публичен и защищён входом ColTex.
- В интернете используйте HTTPS (Caddy, как в конфигурации с облачным сервером).
- Брандмауэр на сервере (ufw, firewalld) не закрывает порты, которые публикует Docker. С `--domain` порт 3690 отвечает только на самом сервере; если вместо этого вы используете Tailscale или туннель Cloudflare, закройте 3690 в брандмауэре облачного провайдера.
- Открытой регистрации нет, только приглашения; к паролям применяются правила надёжности; вход разрешает 3 попытки за 10 секунд с одного IP.
- Нестандартный порт не останавливает сканеры; не полагайтесь на него.
